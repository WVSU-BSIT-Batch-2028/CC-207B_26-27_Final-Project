# CC 207B Final Project Checklist

## App
- [ ] Built in Flutter (web or mobile)
- [ ] UI follows your low- and high-fidelity prototypes
- [ ] Real or realistic client, solving their actual problem
- [ ] Enough core features for your team size (2→3, 3→4, 4→5, 5→6), AI feature included
- [ ] Core features take input, process or change state, and produce a result (login, splash, About and Settings don't count)

## Technical minimums
- [ ] Value, Layout, Interaction and Navigation components used (in design and in code)
- [ ] Smooth navigation between screens
- [ ] At least one form with input validation and clear error messages
- [ ] Data persistence (local storage or Firebase)
- [ ] Async operations show loading, empty and error states
- [ ] Folders organized by purpose (screens, widgets, models, services, assets)
- [ ] Comments explaining each significant part of the code

## AI feature
- [ ] End users interact with it directly
- [ ] Solves a real problem, and you can explain why AI beats plain logic
- [ ] No API keys or secrets in the repo
- [ ] Loading state, timeout and error handling, plus a usable fallback
- [ ] AI output is labeled, and users can correct or override it
- [ ] Collects only the personal data it needs (RA 10173)

## Documentation
- [ ] Overview: app name, purpose, target users or client, tech stack with versions
- [ ] Packages used and the purpose of each
- [ ] Low- and high-fidelity prototypes
- [ ] Core features with screenshots and descriptions
- [ ] Topic Coverage Matrix (layout, navigation, forms, async/API, persistence, AI) with file and class
- [ ] AI Feature Spec: service/model, inputs/prompts, sample outputs, failure handling and fallback, known failures, why AI, privacy
- [ ] Known limitations, planned features and improvements
- [ ] AI Usage Log (appendix)
- [ ] Individual reflections, about half a page each: what you built, one bug you fixed and how, what you'd do differently

## Presentation
- [ ] PowerPoint or PDF, 5 to 10 minutes
- [ ] Background: problem, target users, purpose
- [ ] Core features, including the AI feature
- [ ] Screenshots
- [ ] Live demo, plus a recorded backup video
- [ ] Known limitations and future plans
- [ ] Each member ready to explain their own code and make a small live change (2 to 3 minutes)

## GitHub
- [ ] Fork the org repository and add teammates
- [ ] Feature branches with meaningful commit messages
- [ ] Every PR reviewed by at least one teammate before merging
- [ ] Secrets excluded with .gitignore
- [ ] README with setup and run instructions
- [ ] All members commit steadily, not just near the deadline
- [ ] Team leader opens the final PR to the main repository

## After the presentation
- [ ] Self and peer assessment completed (ratings tied to verifiable GitHub contributions)
- [ ] Files submitted on the LMS on time (late work loses 5 points per day, up to 7 days)
